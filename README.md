Draftbridge
===========

Synchronize a [Draftling](https://github.com/clackups/draftling) with a
Git repository on GitHub or Codeberg through a USB cable, from a web
browser, without WiFi. See [AGENTS.md](AGENTS.md) for the outline.

How it works
------------

1. The user logs in with GitHub or Codeberg (OAuth) and chooses the
   repository for the Draftling's documents, or creates a new one. A
   repository that contains files other than Markdown (`.md`), text
   (`.txt`) and Fountain (`.fountain`) is refused, with the list of the
   offending files.
2. On the Draftling: F1 -> "Sync via browser" -> Start. The device
   becomes a Kermit file server on its USB serial port; the browser
   connects to it with the Web Serial API (Chrome, Edge, Opera). On
   opening the port it releases DTR and RTS (RTS first), so boards whose
   USB-to-UART bridge drives the ESP32's reset and boot pins (the Seeed
   reTerminal) keep running; see [docs/kermit.md](docs/kermit.md).
3. Synchronize: the browser performs the steps Draftling's own Git sync
   performs over WiFi -- commit the documents, fetch, fast-forward or
   rebase with a per-line merge (conflicts are committed with markers),
   update the files on the device, push -- on the Git repository the
   device keeps in `.git` on its SD card. It reads and writes that
   repository and the documents over Kermit and talks Git smart HTTP to
   the Git host. The device's `git.cfg` is pointed at the repository.
4. On the Draftling: F1 -> "Sync via browser" -> Stop.

The server is stateless: it serves the web application, swaps OAuth
authorization codes for tokens (that needs the client secret) and
forwards the browser's requests to the Git host (Git hosts do not
accept cross-origin requests from browsers). It stores nothing: the
login lives in the browser tab's session storage, preferences (last
repository, serial speed) in local storage.

[docs/kermit.md](docs/kermit.md) describes the Kermit side.

Requirements
------------

* Node.js 22.18 or newer (runs the TypeScript sources directly in
  development).
* An HTTPS URL: browsers allow Web Serial only on secure pages
  (`http://localhost` counts as secure for development).
* A Chromium-based browser (Chrome, Edge, Opera) on the user's
  computer; Firefox and Safari have no Web Serial.

Running
-------

    npm install
    cp draftbridge.config.example.json draftbridge.config.json   # then edit
    npm run build
    npm start

For local development `npm run dev` bundles the browser code and runs
the server sources without building (set `baseUrl` to
`http://localhost:8090`).

Configuration values can be overridden with `DRAFTBRIDGE_CONFIG` (path
of the config file), `DRAFTBRIDGE_PORT`, `DRAFTBRIDGE_BASE_URL`,
`DRAFTBRIDGE_GITHUB_CLIENT_SECRET` and
`DRAFTBRIDGE_CODEBERG_CLIENT_SECRET`.

Run behind a TLS-terminating reverse proxy. `proxy.maxBodyMb` (default
100) limits the size of a push forwarded to the Git host and
`proxy.timeoutSeconds` (default 300) the time of one forwarded request.
`staticCacheSeconds` (default 60) sets how long browsers may cache
`app.js` and `app.css`.

OAuth applications
------------------

Redirect URIs to register: `<baseUrl>/auth/github/callback` and
`<baseUrl>/auth/codeberg/callback`. Logins use PKCE.

* **GitHub**: Settings -> Developer settings -> OAuth Apps. The default
  scope is `repo user:email` (private repositories need `repo`; use
  `public_repo user:email` to limit Draftbridge to public ones).
* **Codeberg** (or any Forgejo / Gitea instance, set `url`): Settings ->
  Applications -> OAuth2 applications, as a confidential client. The
  default scope is `write:repository write:user` (listing and creating
  repositories). Codeberg's tokens expire after an hour; the browser
  renews them through `/auth/codeberg/refresh`.

The token goes from the browser through the Draftbridge server to the
Git host on every request; the server does not log or store it.
Draftbridge never writes it to the Draftling: WiFi sync keeps using the
token in `git.cfg`, which is removed when the device is switched to
another repository (it belongs to the old one).

Development
-----------

    npm test             # unit, Kermit, sync (against the git binary) and server tests
    npm run typecheck
    npm run check-ascii  # code must be ASCII only (see AGENTS.md)

To test against Draftling's own Kermit server code:

    scripts/build-firmware-host.sh ../draftling
    DRAFTLING_KERMIT_HOST=build/kermit-host npm test
